# 项目业务口径最优拍板记录 2026-11-16

桌面方案《面料行业项目｜测试与缺陷闭环整体方案（终版）》第一节第 4 条授权：「自动联网查询，结合行业标准、国家标准、通用标准综合评估，给出适配项目的最优拍板方案，不将全部决策交由用户决定」。本文据此对 `scheme-audit-4-14-to-4-41-ledger-2026-11-16.md` 列出的 11 项待拍口径给出拍板，取证基准为 `origin/main`（b22d5660）。

拍板原则：仓库现行实现符合行业标准的，裁定「沿用现行」（零成本、零回归）；仓库无现值或现行与标准冲突的，给出明确口径与落点。每项含「行业标准 / 仓库现值 / 裁定 / 依据」。

## 1. 4.16 金额舍入与精度
- 行业标准：人民币到分（两位小数）；计算过程不提前舍入，末端一次 round；通用报表用 HALF_UP（MidpointAwayFromZero），高频批量可用银行家舍入；金额以字符串出参避免精度丢失。
- 仓库现值：税额与含税价 `tax.rs::round_dp(2)`；订单行 `(quantity*unit_price).round_dp(2)` 后再算税（中间提前舍入）；财务分析用 `round_dp_with_strategy(2, MidpointAwayFromZero)`；DECIMAL 仅 serde feature，出参为字符串；`452` spec 已锁米/公斤往返差 0。
- **裁定**：金额展示与落库两位小数；**统一 HALF_UP** 为金额口径；**中间结果不提前舍入、仅末端 round_dp(2)**——现行订单行先舍入再算税的次序与标准冲突，列为待修（见落地项）；DECIMAL 字符串出参保持。
- 依据：行业标准一致（末端一次舍入），财务侧已有 HALF_UP 先例。

## 2. 4.18 红冲/作废后附件去留
- 行业惯例：附件随单据快照保留（审计可追溯），作废/红冲不物理删附件，仅在单据侧标失效。
- 仓库现值：附件是单据 URL 列（`order.rs::attachment_urls`，TEXT[]），非独立级联实体；红冲/作废仅审计标 `RISK_VOID/RISK_REVERSE`，无附件清理。
- **裁定**：沿用现行——附件保留不物理删除，作废/红冲靠单据状态与审计标记体现。与审计追溯要求一致。

## 3. 4.20 多端登录互踢或并存
- 行业惯例：企业内部 ERP 多为并存（多岗位协同），敏感操作靠二次校验；互踢适用 C 端账号安全场景。
- 仓库现值：并存不互踢；`AppClaims` 无 device 字段；`log_login` 记 device 仅日志；revoke 仅在登出/改密/改角色/停用。
- **裁定**：沿用现行——多端并存。补 e2e 明确并存语义（A 端登录不使 B 端 token 失效），避免"疑似缺陷"误报。互踢若日后需要，另立安全性专项新增 JTI 踢出链路。

## 4. 4.21 报价审批阈值与超折扣
- 仓库现值（已成事实标准）：`quotation_approval_service.rs` 的 `10万/50万` 三档（Salesperson/SalesManager/GeneralManager）；超折扣阈值读配置表 `quotation_discount_approval_configs.over_discount_threshold_pct`（默认 10.00），`max_discount_pct > threshold_pct` 强制主管审批；`469` spec 已锁越权拒绝。
- **裁定**：沿用现行——阈值以代码常量+配置表为唯一事实来源，不写死测试期望值，断言从配置读。刚好等于阈值按「不超」处理（`>` 才触发）。

## 5. 4.22 主数据改名/改价与历史回溯
- 行业惯例：价格取快照（下单即锁定），主数据改名同步展示名但历史单据用快照名；改价不回溯历史单据。
- 仓库现值：`quotation_convert_service.rs` 转单时复制 `unit_price/base_price/final_price` 入订单行（快照）；`color_price_history` 只记历史无写回；历史单据名由 DTO 快照列承载。
- **裁定**：沿用现行——价格快照、改价不回溯；客户/面料改名后历史单据显示快照名。与 `PurchaseOrderDto` 快照范式一致。

## 6. 4.23 报表口径（同比环比/跨期/红冲/实时性）
- 行业惯例：同比=去年同月、环比=上月；红冲以状态或冲销单体现；实时查询+缓存适用于中小数据量。
- 仓库现值：`bi_analysis_ops/profit.rs` 按 `to_char(order_date,'YYYY/MM')` 自然月算同比环比，`status NOT IN (cancelled,draft)` 过滤，实时查询+`try_get_cache`。跨期归属与红冲冲销无专门规则。
- **裁定**：同比/环比沿用自然月口径；红冲单以「状态=作废/红冲」剔除（与现行一致），不另做金额冲减归集；跨期调整与 T+1 物化视图**本轮不建**（数据量未达阈值，实时+缓存已够），登记为未来优化项。

## 7. 4.30 时区与日界
- 行业标准：数据库 UTC 存储、前端本地展示；日界归属以业务时区为准（本仓业务在中国，UTC+8）。
- 仓库现值：时间字段普遍 `DateTime<Utc>`；前端 `toLocaleString('zh-CN')` 转本地；`audit_enhanced_handler.rs` 结束日取 `23:59:59 and_utc()`（按 UTC 算日界，与业务时区有偏差）。
- **裁定**：存储 UTC 保持；**日界维持现行 UTC 口径**——影响面评估发现全后端一律 UTC、无业务时区常量、该 handler 纯日期分支无前端消费者；孤立改 UTC+8 会造成与同 handler 的 RFC3339 分支语义割裂、跨 UTC 日归属整体左移 8 小时。若未来确需按本地业务日过滤，须先建统一业务时区常量并全链路评估，不作为本轮落地项；前端展示转本地保持。

## 8. 4.33 审计留存期与高风险标记
- 仓库现值：`AUDIT_RETENTION_DAYS` 默认 365 天自动清理；`audit_logs.risk_flag` 取 `DELETE/REVERSE/VOID`，删除自动落、红冲作废由业务侧 `mark_audit_high_risk` 写。
- **裁定**：沿用现行——留存 365 天、高风险三值标记。符合一般企业审计留存实践，且实现已在。

## 9. 4.37 色差/计量
- 仓库现值：`bulk_color_approval_service.rs` ΔE ≤1.2 通过 / ≤2.5 让步 / >2.5 不合格（强光敏感 0.8/2.5）；`dual_unit_converter.rs` 公斤=米×克重×幅宽m÷1000（round_dp(3)）、码/米=1.0936、容差 0.005；缩水率只有检测项无阈值。
- **裁定**：沿用现行 ΔE 三档与换算系数（已由 `210/212/452` spec 锁定）；缩水率阈值**不拍具体数值**——按客户工艺单输入而非全局常量（不同面料缩率不同），登记为「按单据配置」口径，避免臆造统一值。

## 10. 4.40 多组织/多仓/多公司
- 仓库现值：数据域单值 `DataScope{All,Dept,Self_}`，dept=归属人∈可见部门成员集合；**无 company_id/organization_id、无跨公司抵消**。
- **裁定**：多仓沿用现行（调拨守恒已由 `450` spec 锁定）；**多公司维度本轮不建**——仓库无组织实体，引入需新增 organization 域+数据迁移，属新功能非口径问题，登记为独立专项。权限范围沿用单值枚举，不擅自改交集/并集语义。

## 11. 4.41 转单快照/未审批重算/红字核销
- 仓库现值：转单复制价格字段入订单、报价置 `converted` 终态不可取消（`517` spec 已锁）；未审批单据随额度变化重算**无现值**（提交时才 `check_credit_available_txn`）；红字核销走 `cancel_verification`（COMPLETED→CANCELLED 恢复发票金额）与 AP `cancel`。
- **裁定**：转单沿用快照、不可回溯（已闭合）；**未审批单据裁定为提交时校验额度、过程中不自动重算**——沿用现行，避免审批中途额度变动引发状态抖动；红字核销沿用 cancel 解绑（已闭合）。

## 落地项（裁定与现行有冲突，需改代码+补断言）
1. **4.16 中间舍入次序**：订单行金额计算改为末端一次 round_dp(2)（先乘后舍、税额基于未舍入金额），补 50+ 行合计差额为 0 的断言。落点：`services/po/order_ops/crud.rs::calculate_item_amounts` + 平行实现 `po/price.rs::suggestion_line_amounts`（两者须同步，避免人工/自动补货口径分裂）。影响面评估：现有 contract/e2e 样本乘积均为整数或两位小数，改次序值不变，无连锁红风险。
2. ~~4.30 日界业务时区~~ **已撤销**：影响面评估结论为维持现行 UTC（详见 4.30 裁定），本轮不改代码。
