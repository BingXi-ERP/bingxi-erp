# 安卓端全应用优化实施计划

> **执行要求：** 按波次逐项执行；每项完成独立复审与验证后才进入下一项。禁止本地构建、cargo build/test、启动开发服务器或本地 Playwright。真实业务和设备验证走 CI／授权安卓设备。推送须另有明确授权。

**目标：** 对 HTTPS 公网部署下的安卓 Tauri WebView 应用实施全应用、全流程、全生命周期优化，优先重组手机功能排版，并完成全部业务域、原生能力、安全、性能、兼容性与发布验收闭环。

**架构：** 保留 Vue 3、Element Plus、现有业务 API 与 Tauri/Kotlin 原生桥；共享业务状态，只按安卓手机、平板和桌面拆分必要的表现布局。以路由×功能×角色×状态×设备矩阵作为覆盖分母，先完成壳层和代表页，再逐域迁移；扫码、打印、导出和弱网写入必须用真实回读与设备证据验收。

**技术栈：** Vue 3、TypeScript、Element Plus、Tauri 2、Rust、Kotlin、Playwright E2E、GitHub Actions。

**设计依据：** `.monkeycode/docs/mobile-h5-android-optimization-assessment-2026-11-15.md`

## 全局约束

- 目标部署为 HTTPS 公网；不开发 HTTP 内网兼容分支，测试 HTTP 降级、证书错误、混合内容和不可信来源拒绝。
- 安卓手机功能排版是首要设计目标；六类代表页只是样板，不是最终覆盖边界。
- 全部可达路由、页内重要 Tab／弹窗／状态、角色差异和安卓能力均须进入矩阵；静态命中、未执行、跳过和通过分开记账。
- 遵循 `agents.md` 与 `.monkeycode/MEMORY.md`：本地只跑许可的静态检查；禁止本地构建、cargo test/build、起服务和 Playwright。
- 不盲目重放出入库、审批、付款等写操作；超时先回读，逐端点确认幂等能力。
- 不持久缓存敏感业务数据、权限或认证令牌；不以 CSS 隐藏代替数据权限。
- 复用现有扫码、蓝牙打印、系统打印、导出审批和一次性下载令牌链；不把桥调用成功描述为业务完成或实际出纸。
- 不修改 CI、权限配置、原生桥来源策略、签名与发布配置，除非该波具体任务及用户授权明确覆盖。
- 每个功能域一支载体；本计划不授权创建分支、提交、推送、PR 或生产变更。
