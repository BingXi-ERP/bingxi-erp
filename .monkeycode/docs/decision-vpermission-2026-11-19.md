# v-permission 无权限按钮「移除 vs 灰化+说明」最优拍板（2026-11-19）

## 一、决策问题与授权依据

目标 4.1 O 要求「无权限按钮灰化时鼠标悬浮有 tooltip 说明原因」，与 4.1 A「无权限角色不显示或灰化」并存；仓内 `directives/permission.ts` 三处 `removeChild`（27/46/68 行），481-03/482 用例以 `count()==0` 固化了「移除」语义。`capability-gap-2026-11-03` 与 `scheme-audit-2026-11-14` 均把本项列为待拍板，后者明确「须按按钮与容器分别评估，不能因既有测试要求隐藏就判定新增要求不适用」。

目标明确授权「项目决策支持，自动联网查询，结合行业标准、国家标准、通用标准综合评估，给出适配项目的最优拍板方案，不将全部决策交由用户决定」。故本项自主拍板，不回问用户。

## 二、联网取证（国际标准 / 国家标准 / 通用实践三源）

### 国际标准 WCAG 2.2

- 1.3.1 Info and Relationships（A 级）：视觉上传达的状态与结构必须以程序化方式供辅助技术读取。
- 4.1.2 Name, Role, Value（A 级）：交互控件的名称、角色、状态必须可程序化判定。
- 原生 `disabled` 由浏览器暴露禁用状态，读屏可播报「button unavailable」；`removeChild` 后元素不存在于无障碍树，读屏用户无从知晓该能力存在，更不知「为何不可用」。

### 国家标准 GB/T 37668-2019《信息技术 互联网内容无障碍可访问性技术要求与测试方法》

- 可感知性：文本颜色不得作为传达信息的唯一手段，控件状态不能只靠视觉呈现。
- 键盘操作与读屏兼容：所有文本内容应可朗读、焦点顺序正确；被隐藏的元素不进入无障碍树，读屏不可达。

### 通用最佳实践 UCOP eCourse Accessibility Checklist（2025-05-23 更新）

- 判据原文要点：若按钮在某操作后即可用（initially unavailable but becomes available），应禁用而非隐藏——隐藏会让读屏用户无法理解情境，且在按钮变为可用时找不到它。
- WAI / WebAIM 共识：tooltip 不能绑在原生 `disabled` 元素上（禁用元素不触发 hover/focus），须用 `aria-disabled` 保留可聚焦性与状态播报，并由外层包装承载提示。

## 三、仓内现状事实核对

- `directives/permission.ts:27/46/68`：三处 `removeChild`，无灰化分支。
- `flow/481-notification-entry-permission-same-source.spec.ts:203`：无 `users:read` 岗位不应渲染收件人选择器（`count()==0`）；482 对公告卡片同理。
- 全仓 246 处 `v-permission` 使用点（`capability-gap-2026-11-03` 实量）。
- 状态级禁用已有零散范式（如 `bulk-color-approval/index.vue:130` 按 `sales_order_id` 前置禁用），但无「原因 tooltip」。
- 4.1 R 状态门（报价未审批不可转订单）现为 `v-if="canConvert"`（`quotations/approval.vue:92`）——直接隐藏，无状态播报。

## 四、最优拍板：分治，不一刀切

1. **角色级无权限**：RBAC 无对应码（如无 `users:read` 的收件人选择器），**保留 `removeChild` 移除**。
   - 判据：无码即该能力对该角色永远不可用，不存在「条件满足后可用」；移除不制造误导可用性（affordance），不暴露内部能力面；4.1 A 明确允许「不显示」；481/482 断言保持成立，零回归。
2. **状态级临时不可用**：4.1 R 八条时序门（未审批不可转订单、未签收不可对账等）与 4.1 O 灰化按钮，**改为 `aria-disabled` + 外层 tooltip**，保留元素与程序化状态，禁用态显式播报原因。
   - 判据：这类能力「条件满足后可用」，正是 WCAG / UCOP 明确 disable 优于 hide 的场景；`aria-disabled` 保留可聚焦性与禁用状态播报，tooltip 说明解锁条件，与 GB/T 37668「状态不只靠颜色」一致。
3. 灰化 tooltip 文案一律走中英双语 i18n 键（`check-i18n` 校验），不写裸中文；文案只说「该做什么」（如「报价审批通过后可转订单」），不塞实现细节。
4. 高风险按钮（删除 / 红冲 / 作废）保留二次确认，灰化不替代确认。

## 五、另外两案为何不选

- **全量改灰化**：246 处使用点加 481/482 断言翻红，须同支改用例，爆炸半径大；且对「永不可用」能力制造可点不可用的误导。
- **全量保持移除**：状态级能力被隐藏，违反 WCAG 1.3.1 / 4.1.2 的状态可程序化判定与 4.1 O / R，读屏用户无法理解单据为何不能推进。

## 六、落地路径与验收（本 PR 不改源码）

- 本 PR 仅落决策与判据（纯文档，授权直合），避免触碰 246 处与 481/482 导致大面积回归。
- 后续开发：新增 `v-state-disabled` 指令或扩展 `permission.ts` 的 `aria-disabled` 分支，仅用于状态级；补 E2E 断言 `aria-disabled="true"` + tooltip 文案键存在 + 点击被后端拒绝；481/482 因角色级口径不变无需改。
- 验收：4.1 A / O / R 三节逐条有独立无痕角色 + 状态双分支断言；`check-i18n` 通过；无障碍读屏面（`aria` 状态、tooltip role）在 E2E 有断言。

## 七、结论

采纳「分治」方案。角色级无权限维持移除以守住回归与口径；状态级不可用改 `aria-disabled` + tooltip 以符合 WCAG 2.2、GB/T 37668-2019 与目标 4.1 O / R。该项从「待拍板」转入「已拍板」，落地实现按第六节另开工单跟进，不在本文档范围内。
