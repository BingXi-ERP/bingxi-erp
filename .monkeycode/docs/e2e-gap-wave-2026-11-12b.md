## 二、本轮落地的功能补全（测试暴露的缺陷，源码面补齐，不靠用例凑绿）

- 订单编辑并发冲突（补测专项 4.2 与 4.1 D 段的冲突提示一条）：写面在事务内排他锁之后、任何写入之前比对客户端回填的更新时刻令牌，不等即业务族拒绝且零写入；不带令牌保持既有行为兼容存量调用方。前端编辑表单装载时读回该行更新时刻、保存时原样回传，冲突拒因经统一信封外显。载体 PR #1212，用例 473。此前台账记的"仍无实现落点"到本轮为止。
- 产品编码重复拒因不可辨：产品建档口此前不预检编码重复，重复编码裸撞库级唯一约束被归成 DATABASE_ERROR，对外只剩脱敏文案，操作者分不清重复还是库故障。补为按通用导入腿同一口径点名重复并走业务族，CSV 导入腿汇进同一入口同步受益。载体 PR #1214。
- 色号唯一性整维度无防线：产品色号表既无库级唯一约束、服务层也不查重，同一产品下重复色号会静默落多行。补为服务层前置查重，判据作用域是同一产品内的色号，换色号照旧放行。不加库级约束的理由：存量重复行会把建约束的迁移直接挡在建库期，这一步未做也未验证清理口径，登记为在途。载体 PR #1214，用例 505。

## 五、本轮取证与取数口径的两处不老实登记

- 开放 PR 数取成零：一次用列 PR 端点判当日红面时，请求被 403 限流挡回但脚本未打印状态，空数组被读成"开放 PR 为零、全部已合入"，据此得出过"五支车道的 PR 都已消失"的错误结论。实际五支 PR 一直在开。修正口径：列端点必须先证明 HTTP 状态为 200 才采信条数，零条要区分"确实零条"与"取数失败"。
- 推送退出码被管道吞掉：一次把 git push 的输出接 tail 判绿，取到的是 tail 的退出码，网络中断导致的 rc 128 被掩盖成成功。修正口径：先取 git 自身退出码再截断展示，远端是否真的动了只认 ls-remote 回读。
- 本地按单文件跑裸 rustfmt 与仓库钉版工具链的折行判定双向不一致：本轮对 so 目录内多个主干既有文件报出差异行，实际那些文件在主干上是过格式门的。已整片还原不带进改动，格式面交 CI 的 cargo fmt 判，本地只用作提示。
