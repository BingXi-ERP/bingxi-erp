- 命中面：410 号十一腿（缺料阈值写入回读与按阈值定级、账龄规则写读三态、账期逾期扫描触发幂等与通知回读、批色提醒阈值与去重窗口、批色超时自动拒绝阈值边界）、454 号七腿（账期规则建改查、审批超时提醒门控且不自动拒他人单据、应收逾期真实触发落库并按规则角色集投递站内信、二次触发不翻倍、非角色集岗位不可见）、501 号四腿（重复触发不重复建单、只投启用规则声明岗位且不重复投递、审批超时不降级给触发者、库存预警重复读取不新增站内信）——①条全断言链闭合；98 号六腿加 118 号三腿（订阅整行建读、toggle 停用回读、PUT 部分更新、四道校验门、手动触发与立即发送逐键回读、软删过滤）——②条幂等与订阅面闭合。
- 结论：4.6 两条主述均无假覆盖（文件名命中且腿是真实 API 断言），无需立新补测；五个 scheduler 域（缺料/账龄/账期/批色/审批超时/库存/财务预警/报表订阅）的触发-投递-幂等三段全部有钉面。后续按条实量按 4.7 顺序推进。

## 七、4.7 消息通知链路按条实量（目标四逐条口径第二枚）

- 实量范围：目标 4.7 两条主述——①站内与微信订阅消息渠道触达校验 ②消息不推错人/不泄露敏感数据/失败重试/防重复轰炸。
- ①命中面：504 三腿（不推错人 owner 隔离真实列断、读面出参键集恰为表列且无手机号成本价、同请求 user_ids 重复三次只落一行）、454-06 非角色集岗位不可见、501-02 只投启用规则声明岗位、510 双通道（审批通过与拒绝腿站内信落库实断）。微信腿：EventNotificationService 双通道出口在，CI 无 WECHAT_MP_* 凭证按设计跳过且断言不阻断主流程（510-01），发送面属凭证环境实测范围不是 e2e 覆盖缺口；后端 outbox 队列（enqueue/list_pending_for_retry/mark_as_sent/increment_retry）与 worker run_once 落点真实存在（失败重试真有实现），outbox 为纯后台 worker 无 HTTP 路由，e2e 无法直接驱动，属架构边界。
- ②命中面：504-1/504-3 钉不推错人与防重轰炸；失败重试的钉面在 outbox worker（increment_retry 落点），e2e 层由 504-3 与 501 幂等族间接守恒。
- 结论：4.7 两条主述在 CI 可达范围内全部闭合，无假覆盖无缺口；微信发送面与 outbox 重试面是凭证环境实测事项，登记到非 e2e 边界即可，不立补测。

- 结论：4.8 四条主述闭合；SQL 注入弹与 CSRF 深度攻击面属架构层验证（SeaORM 参数化、helpers CSRF 恢复全量生效），不立补测。
