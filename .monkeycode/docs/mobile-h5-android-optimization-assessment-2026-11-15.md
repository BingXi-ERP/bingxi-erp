## 三、路线比较与推荐架构

| 路线 | 收益 | 代价与局限 | 建议 |
|---|---|---|---|
| 继续追加全局 CSS | 上手快，简单溢出可集中修 | 不能解决信息层级、连续扫码、审批效率；强制规则容易互相覆盖 | 仅用于明确的基础缺陷，不作为总方案 |
| 同一业务、分层响应式布局 | 复用接口、权限、状态机及原生桥；桌面和手机保持业务一致 | 需要页面分类、代表页设计与桌面回归 | 推荐 |
| 独立移动前端或原生重写 | 移动自由度高 | 双份状态与权限维护、接口联调和长期回归成本大 | 当前不推荐，无性能证据支撑重写 |

推荐分四层：

1. 设计与壳层：既有主题增加移动尺寸、触摸、间距和层级约定；统一顶栏、导航、内容区、安全区。
2. 页面表现层：列表卡片、详情分组、表单分段、筛选面板、操作栏等少量真实复用模板；先验证代表页，再提炼组件，不预造复杂通用渲染框架。
3. 业务状态层：继续使用现有 API、组合函数、后端状态与权限。卡片与表格共享同一份数据和操作，不重复请求、不复制审批规则。
4. 设备能力层：H5 与 Android 分别检查实际能力；复用现有扫码、打印桥。硬件缺失、权限拒绝和服务错误分别解释，禁止假成功。

布局按容器宽度决定；触摸大小由指针能力和场景决定，不仅按 UA 或宽度判断。先保留现有 768、992 断点含义，统一交界规则；若设计后要改变，必须与 CSS、组合函数、测试一起调整。

## 四、移动界面目标设计

用户已明确强调：安卓端必须针对手机屏重新组织功能排版。本方案因此以安卓手机的功能分组、信息层级和单手操作为首要设计目标，H5 复用适用成果，平板与桌面保持各自布局。不将“缩小字号、压缩表格、菜单改抽屉”当作手机优化完成。

以下尺寸和具体布局是提议的设计目标，不是现状实测值，也不是已批准设计令牌。安卓优先确定了设计重点，不代表新增功能、配置修改或代码实施已获授权。

### 4.1 视觉与可读性

- 延续现有品牌及亮暗主题，不同时重做品牌。状态同时用文字和图形表达，不只靠红绿颜色。
- 内容左右留白通常 12 至 16 CSS px，区块间距 12 至 16，区块内部 8 至 12；统一映射到主题令牌，避免各页散落魔法数。
- 正文和输入建议 16px，辅助文字 14px，标题 18 至 20px；金额、米数、重量独立对齐，保留单位和业务精度，不因窄屏截掉关键数值。
- 主要触摸目标至少 44×44 CSS px，仓库主操作优先 48×48；这是产品目标，不把 44px 描述为所有 WCAG AA 情形的唯一阈值。
- 普通文字对比度至少 4.5:1，大文字和必要非文字控件至少 3:1；暗色、禁用、错误、聚焦分别验收。200% 字体放大后仍能完成主流程。
- 动效只用于状态反馈和方向提示，优先 150 至 250ms，支持减少动态效果；扫描反馈不用持续装饰动画。

### 4.2 壳层与导航

建议手机主壳由“紧凑顶栏、当前业务内容、常用导航”组成：顶栏保留当前页标题、搜索入口及必要通知；常用导航建议工作台、待办、作业、更多四项，最终按真实业务与权限确定，不强行给无权限用户留空入口。

底部导航不应在全屏扫描、编辑单据、图片预览时与业务底部操作栏竞争；这些场景让业务操作优先。保留完整功能目录的可搜索入口，不能以菜单轻量化为由删除低频但必要功能。首页允许按已授予能力组织快捷入口，不另写一套角色权限真相。

页面内状态返回后可恢复：筛选、分页和滚动位置分开管理；优先使用会话内状态，URL 仅放允许公开的非敏感筛选，不把客户隐私或金额条件随意写入 URL。

### 4.3 六类页面布局规范

| 页面类型 | 手机布局 | 平板与桌面对照 | 必须保留 |
|---|---|---|---|
| 工作台、统计看板 | 待办优先；指标一至两列；图表逐块展开 | 空间允许多列，沿用桌面密度 | 指标时间、口径、单位、钻取 |
| 常规业务列表 | 标题和状态在首行，3 至 5 项关键摘要，详情展开；搜索常驻、复杂筛选入面板 | 平板可主从双栏，桌面表格 | 服务端分页、筛选、总量和操作权限 |
| 对账、财务、密集比较表 | 不机械卡片化；固定识别列、字段分组、局部横滚及滚动提示 | 宽屏保留比较效率 | 合计、精度、行列关联和导出 |
| 业务详情 | 单据标识与状态置顶，基本信息、明细、附件、流程记录分组 | 宽屏双栏或原有描述表 | 长编号完整查看，字段和审计记录不丢失 |
| 创建、编辑表单 | 顶部标签、单列、分段；明细行卡片编辑；保存操作靠近拇指区 | 宽屏保留高效多列和批量录入 | 校验、依赖字段、总额与未保存提示 |
| 审批、扫码任务 | 任务摘要突出，主操作固定，次操作收起；危险操作确认 | 桌面仍用表格或任务面板 | 业务状态、权限、拒因、结果回读 |

卡片化不是删字段：摘要之外提供详情入口；不将所有表格强制替换为卡片。长备注、长客户名、多语言标签、空值和超大金额必须有设计样例。

### 4.4 表单、选择器和软键盘

- 数字、米数、重量和金额使用适当 inputmode；输入键盘只是交互提示，提交仍按真实 DTO 和精度校验。
- 客户、供应商、仓库、产品及关联单据沿用可搜索选择器，不让用户手填数据库 ID。选择器需容纳长名称、分页结果、无结果和加载失败。
- 日期范围采用适合窄屏的起止选择；保留后端日期语义，不因展示调整时区。
- 校验先定位第一个错误，再给字段级原因；错误不是只弹短暂 toast。保留填写内容，避免一个字段失败整单重填。
- 软键盘弹出后，聚焦字段、提示和主要按钮不能被遮挡。内容和操作栏依据可用视口变化布局，避免多个滚动层相互争抢。
- 离开未保存表单时提示。首阶段只保留当前会话草稿；涉及持久化的敏感草稿另按缓存策略验收。

### 4.5 弹窗、抽屉和交互反馈

短确认保留居中弹框，短选项适合底部面板；复杂编辑改为全高面板或现路由内的编辑状态，不叠加三层弹窗。聚焦顺序、关闭后焦点恢复、系统后退和页面返回保持一致。

每个页面必须设计加载、空数据、筛选无结果、错误、权限不足、离线、内容过期和提交结果未知状态。无权限隐藏继续遵循既有安全约定；仅业务前置不满足的已授权动作禁用并解释原因，不统一改写 v-permission 行为。

### 4.6 安卓手机功能排版专项：首要交付项

#### 功能组织规则

- 按“当前要完成的任务”组织入口，不把桌面部门目录或所有功能图标平铺到手机首页。完整模块目录留在“更多”，并提供搜索；常用任务仍按既有权限过滤。
- 首页首屏优先显示当前待办和可执行任务，其次是常用入口，统计和长图表后置。没有授权或没有数据时呈现真实状态，不制造指标和待办占位。
- 每个操作区域只突出一个主操作；必要时保留一个清晰的次操作，其他操作收进带文字的“更多”。拒绝、删除等高风险操作与正向主操作保持视觉区分及安全间距。
- 手机布局以单列主内容为默认；少量指标可两列。一个页面采用明确的主滚动容器，避免页面、卡片、表格三层同时纵向滚动。
- 默认正常字号与键盘关闭时，首屏能识别页面用途、当前业务上下文与主要入口；字体放大或短屏时允许滚动，不能为挤进首屏缩小字体、裁切内容。

#### 重点屏幕排版蓝图

| 屏幕 | 从上到下的内容顺序 | 主操作与次要功能 | 必须解决的手机问题 |
|---|---|---|---|
| 工作台 | 紧凑标题／搜索，待处理任务，常用功能，业务摘要 | 常用入口直达既有流程，完整功能放“更多” | 避免首页成为桌面菜单墙；按权限显示，不硬编码岗位特权 |
| 业务列表 | 页名／新建，搜索／筛选入口，已选条件摘要，业务卡片，分页或加载更多 | 卡片正文进入详情，行级次操作进“更多” | 不在首屏铺满筛选表单；返回恢复筛选和位置；分页形式沿用服务端能力 |
| 单据详情 | 单号／状态，往来单位及关键金额或数量，明细，附件／流程记录 | 当前状态允许的主操作置底，历史与低频动作折叠 | 重点信息不用左右寻找；不能隐藏关键追溯信息；长编号可完整查看 |
| 新建／编辑 | 标题和返回，业务分段，单列字段，逐条明细编辑，校验摘要 | 底部保存或提交，取消和其他动作降级；不能新增不存在的草稿接口 | 不沿用桌面多列密集录入；软键盘不遮挡焦点；总额与校验结果清楚 |
| 审批待办 | 待办状态筛选，任务卡片，业务依据和流程详情 | 查看依据后同意或驳回，转交等进次级操作 | 不在窄表格里寻找小链接；避免滑动误审批及他人处理后的陈旧操作 |

| 对账／报表 | 日期与范围摘要，关键结果，分组明细／图表 | 查看详情、合法导出或打印 | 保留比较所需行列关系；横滚局限表体；金额和单位不被截断 |
| 附件／打印 | 文件或单据摘要，预览区，输出方式与设备状态 | 明确保存、分享或打印，进度／失败原因就近展示 | 不把系统弹窗唤起当成出纸；预览关闭后回到原业务位置 |

#### 导航与操作栏协调

普通浏览页使用顶栏、内容区和底部主导航。进入单据编辑、审批处理、扫码或全屏预览后，以任务级返回和操作栏优先，不让底部导航、保存按钮、悬浮按钮和系统导航叠在一起。键盘出现时隐藏无关导航或调整操作区域，但必须保留可发现的提交与取消路径；最终行为由真实 Android WebView 和输入法验证。

弹出选择器优先使用适合手机的全高或底部面板，搜索和选中结果清晰可见。长表单可以按业务分段折叠，但不为了减少页面长度强加每步都要确认的向导；跨段校验失败时自动展开并定位字段。

#### 安卓优先的设计与验收顺序

先交付工作台、业务列表、详情、编辑、审批、扫码六种代表屏的手机设计，再补密集报表与输出流程。以 360、393、412 CSS px 为主设计宽度，320 为极窄边界；至少一组短屏、横屏、软键盘及200%字体场景。不能只提交桌面截图或浏览器改宽截图作为安卓最终验收。

每屏设计说明须标明首屏内容顺序、主次操作、可折叠区、返回路径、权限差异和异常状态；按真实任务比较优化前后操作步骤与误操作点，再设效率目标，不凭空承诺统一减少百分比。安卓真机确认排版和交互后，再验证 H5 同布局兼容性及桌面不回退。未取得设备证据时只能报“设计完成／待真机验证”，不能报“安卓优化完成”。

## 五、全部业务线的优化清单

### 5.1 仓库与 PDA 作业

工作流：选择合法业务上下文，再扫码识别，核对产品／批次／缸号／色号／匹号及数量，提交后回读结果。扫描框、识别摘要和主操作优先，不把大段历史列表放在首屏。

摄像头扫码与 PDA 扫码枪分面：先支持已有摄像头及键盘输入式设备，厂商广播／SDK 型设备按目标硬件另接。连续扫描采用显式作业模式，区分识别中、待确认、提交中、已受理、失败；重复条码是否允许由业务决定，不能全局屏蔽同码。

已有的扫码查询和发货腿先优化。入库、盘点等场景必须逐一确认现有写端点和完整事务，不把一个“扫描成功”提示冒充业务落库。不靠自动连点提交换速度，拒因要能定位到具体条目并保留上下文。

### 5.2 管理审批与通知

待办卡片展示任务标题、业务主体、金额或关键数量、发起时间、超期标识；信息缺字段时核验后端 DTO，不自行拼假名称。详情中保留依据与流程链。

同意、驳回、转交复用原动作，驳回原因遵守现有业务要求；滑动手势不直接完成不可逆审批。提交防重，遇到他人已处理时提示并回源更新，不能只从本地删卡片当成功。通知深链返回后保留待办列表位置。

### 5.3 销售、采购与客户服务

订单和报价列表突出单号、往来单位、状态、金额及履约信息；新建表单按主体、明细、交付和附件分段。产品选择、数量录入、价格权限和信用／审批限制维持后端规则。对账与签收流程必须能从详情返回原列表，附件和签收证据不可因移动布局被隐藏。

### 5.4 生产、质量与面料信息

流转卡、工序、检验及打样页面按任务和时间顺序组织，关键追溯维度始终可查看。长工序链用分组时间轴或可展开节点，不单靠横向挤压。

色卡图片支持点击全屏、缩放和多图切换；保留色号与版本标识，并提示屏幕颜色仅作参考。图片压缩不能替代原始质检证据；余码、版本、缸号补录若涉及实际功能缺口，应独立核验契约和业务规则，不借布局优化编造功能。

### 5.5 财务、报表及系统管理

财务移动端优先查询、审核和必要单据操作，保留精确金额与凭证关联；复杂配置也必须有可完成的布局，只是排期靠后，不以“请用电脑”作为全面优化的最终交付。

报表先显示结论与口径，再展开图表和明细；图表减少拥挤标签，提供可读数据替代。敏感指标按现有数据权限返回，前端不靠 CSS 隐藏成本列。系统配置、权限管理、初始化和服务器设置同样纳入字体、键盘及长表单检查。

### 5.6 图片、附件、单据与打印

缩略图懒加载并预留尺寸，首屏关键图不延迟；预览支持缩放、手势、关闭及无手势替代按钮。大图按需加载，避免打开列表就下载全部原图。

上传先检查服务端允许类型和大小；照片按场景生成展示副本，保留必须留档的原文件。处理 EXIF 方向、进度、取消、失败重试与大文件内存峰值；不要统一有损压缩扫描凭证、条码或色卡原件。

单据提供适合手机阅读的摘要和完整原文预览。系统打印、蓝牙打印、文件保存、系统分享分别标明能力与状态：系统打印对话框已打开、数据已发送给设备、不确认物理出纸的情形不可写成“打印完成”。蓝牙失败后不得自动反复重打，避免重复标签或单据。

敏感导出须复用 `frontend/src/utils/export.ts:104-119` 的 downloadExportWithToken 链，不把普通下载接口当作敏感下载出口。端到端验收覆盖申请、审批、一次性令牌下载、系统保存或分享：无令牌、失效令牌、重复使用及无权限访问均按后端契约拒绝。下载成功但保存取消时，不盲目重复消费令牌；按服务端支持的合法流程重新取得文件，并告知用户当前阶段。

安卓侧临时文件限制在应用控制的目录，通过受控内容 URI 授予分享目标必要的临时访问权限，结束后按生命周期清理；日志不含令牌和文件敏感内容。已经由用户明确保存或交给其他应用的副本无法保证远程撤回，导出前须说明该边界，并遵守既有导出审批和审计，而不是承诺“撤权后所有文件自动消失”。

## 六、安卓端全应用、全流程、全生命周期优化

范围扩大确认：用户要求安卓端全方面优化，不限于手机核心页面排版。评估分母扩大到全部业务功能、非业务系统页面、原生能力、运行生命周期及安装更新链路；六类代表页只是设计复用样板，不是最终交付范围。界面与功能排版仍为第一重点，其他能力不能只作为附带检查。

本节新增清单为应评估、设计和验收的目标范围，不表示这些问题均已复现，也不意味着所有新能力都应无条件增加。已有能力先核验再优化；缺失能力按真实业务必要性和安全边界给出方案；不适用项须有证据及明确裁定，不能因实现困难自行划出范围。

### 6.1 已识别的安卓能力重点

| 专项 | 优化要求 | 验收证据 |
|---|---|---|
| 原生桥信任边界 | 部署地址确认与重定向后检查 origin；外链交系统浏览器；敏感原生命令限定可信来源 | 未批准来源调用被拒，合法部署切换可用；具体 Tauri 能力配置方式先做兼容验证 |
| HTTPS 与服务器设置 | 按已确认的 HTTPS 公网部署设计；拒绝 HTTP 降级和混合内容，区分 DNS、TCP、TLS、证书、服务不可达与登录失效 | 不能把 TCP 通等价为 ERP 可用；不忽略证书错误；外部 HTTPS 站点不自动成为原生桥可信来源 |
| 系统后退 | 收键盘、关最上层面板、页面返回、最后退出的明确优先级 | 无重复返回、无误退作业、未保存内容有提示 |
| 生命周期 | 切后台停止不需要的相机任务；恢复时核验登录与业务新鲜度 | 后台回前台、锁屏、进程被回收后的真实恢复记录 |
| 安全区与软键盘 | 复用现有安全区变量，检查安卓 WebView 实际值；必要时桥接系统 Insets，防重复加边距 | 状态栏、三键导航、手势导航、键盘各组合实测 |
| 权限 | 请求前解释，拒绝、永久拒绝、设置恢复分别处理 | 相机及蓝牙的真实系统授权路径，不只验 manifest |
| 文件保存与分享 | 先核现有 WebView 下载；不足时使用系统选址和受控内容 URI，不申请无关全盘权限 | 中文名、MIME、大文件、用户取消和分享目标不可用 |
| 硬件与发布 | 现有经典蓝牙 SPP 不等同 BLE；按设备协议适配，记录安卓与 WebView 版本 | 实机连接、断连、中文标签、纸宽；debug 与 release 差异复验 |

源码疑点而非既定缺陷：蓝牙实现调用 cancelDiscovery，权限注入是否满足目标 Android 版本要求需专项核验；未证实前不直接增加权限或宣称已有崩溃。

### 6.2 应用壳、启动和账号全链路

安卓端不只评登录后页面，还要从安装后首次启动开始评估：

- 首次启动：APK 安装、首次打开、首次加载公网 HTTPS、服务器地址或 gateway 设置、加载失败、重新打开和升级后首次启动。启动屏不展示过期业务数据，不让用户停在无解释的白屏或无限转圈。
- 登录与会话：登录成功、密码错误、验证码或二次认证、会话过期、主动退出、切换账号、账号被禁用、权限变化、网络恢复和进程重建。退出或换账号后清理页面缓存、草稿、通知徽标、原生设备状态及站点关联状态。
- 首屏职责：区分启动加载、登录页、服务器连接设置、登录后工作台和错误恢复页；每个页面有明确下一步，不让“重试”重复提交登录或业务写操作。
- 多窗口与重入：从系统最近任务返回、重复点击应用图标、通知打开应用、外链拉起应用、旋转屏幕及进程被系统回收后重新进入，均要回到合法状态，而不是叠加多个主壳或显示上一用户页面。
- 更新提示：新版本、前端资源更新、服务端版本不兼容和缓存清理分别提示；更新期间不得丢失未提交表单，也不能让旧 HTML 和新脚本混合运行。

### 6.3 系统导航、手势和设备形态

- 系统返回按层级执行：先关闭键盘，再关闭下拉／底部面板／弹窗，再退出详情或编辑页；正在扫码、打印、审批和提交中的操作必须先给出安全处理，不用返回键静默取消或重复触发。
- 全面覆盖手势导航、三键导航、状态栏、刘海、打孔屏、底部手势区、横屏、折叠或窄屏平板；固定顶栏、底部导航、浮动按钮、业务操作栏不得互相遮挡。
- 触摸之外评估蓝牙扫码枪键盘输入、实体返回键、音量键误触、外接键盘、鼠标和触控笔；键盘输入设备不能被页面自动聚焦和软键盘抢占。
- 长按、滑动、拖拽、双击和缩放只能作为增强操作，所有关键业务动作必须有可见按钮或等价键盘路径。滚动区域要明确，避免横向表格和纵向页面互相抢手势。
- 屏幕方向按业务确定：扫码、审批、编辑默认竖屏；密集对账和打印预览可允许横屏，但旋转期间保留数据、焦点、滚动位置和当前操作上下文。

### 6.4 通知、分享、外部唤起和系统协作

- 通知仅展示用户有权看到的最小摘要，不在锁屏暴露客户、金额、成本、凭证和条码等敏感信息；点击通知先校验会话、权限和对象当前状态，再进入详情。
- 通知到达、点击、重复点击、过期、撤权、账号切换和应用未启动分别处理；通知深链打不开时提供可解释错误和安全返回，不展示上一身份数据。
- 文件分享采用系统分享面板时，按导出权限和一次性令牌链路生成临时内容 URI；分享目标取消、目标应用不存在、发送失败和临时文件清理都要有结果。
- 外部浏览器、邮件、即时通信、相机、文件管理器、打印服务和蓝牙设置属于外部边界；返回应用后重新核验数据，不假定外部操作一定成功。
- 若未来接入桌面快捷方式、应用链接、二维码拉起或分享回调，必须建立允许域名、参数签名、过期时间和权限复核，不直接信任外部 URL 中的业务 ID。

### 6.5 文件、照片、相机、扫码和打印的完整设备体验

- 相机：权限说明、首次允许、拒绝、永久拒绝、系统设置恢复、前后摄切换、锁屏／切后台、无摄像头、相机被占用、低光、连续扫描、扫码枪输入和手动输入分别验证。
- 图片：拍摄、相册选择、旋转方向、超大图、模糊图、重复选择、取消、上传中断、重试、删除和预览。展示缩略图与原始留档分开；压缩不损害色卡、质检、条码和凭证证据。
- 文件：下载、保存位置选择、中文文件名、MIME、同名文件、磁盘不足、权限拒绝、用户取消、分享、清理和再次打开。浏览器 Blob 下载与安卓系统保存不是同一成功标准。
- 扫码作业：摄像头识别成功、识别失败、条码格式不支持、业务对象不存在、对象状态不允许、重复扫描、网络超时和结果未知全部明确显示；“已识别”不等于“业务已落库”。
- 打印：设备发现、配对授权、连接、断开、重连、纸宽、中文、条码、空纸、离线、取消、超时和多次点击。系统打印对话框打开、数据发送、打印服务完成和纸张实际出纸分成四个状态。

### 6.6 数据安全、隐私与客户端防护

- 原生桥调用按来源、命令、用户动作和业务权限四层收口；HTTPS 公网来源仍需经过可信站点校验，不能把任意 HTTPS 页面视为可信应用。
- WebView 调试、远程导航、外链、重定向、混合内容、证书错误、脚本注入、文件 URI、下载内容和剪贴板分别做安全评估；不以关闭校验或放宽来源解决兼容问题。
- 认证 Cookie、刷新信息、设备标识、导出令牌和临时文件按最小留存原则处理；不把令牌、完整客户信息、完整条码或凭证内容写入日志、剪贴板、通知或崩溃上报。
- 截屏、录屏、最近任务缩略图、后台快照和应用切换动画可能泄露敏感数据；按业务敏感等级决定遮罩或禁止，不能对所有页面一律阻断而破坏使用。
- 服务器切换、退出、换账号、撤权、卸载和清除应用数据都要验证数据生命周期；尤其检查上一站点和上一用户的缓存是否可见。
- 依赖、APK 签名、发布产物、权限声明、第三方 SDK、调试开关和源码映射按发布档复核；debug 可用不代表 release 安全。

### 6.7 性能、内存、功耗和稳定性

- 启动性能分为 APK 启动、WebView 初始化、首个静态资源、登录后首屏和业务数据可交互，不用单一“打开速度”掩盖慢点。
- 评估低内存设备、长时间运行、长列表、图片密集详情、多 Tab、频繁扫码、连续打印、反复进出页面、旋转和切后台后的内存增长与崩溃。
- 网络性能分别记录 DNS、TLS、首字节、API、静态资源、图片、脚本和渲染耗时；缓存命中不能掩盖过期数据和权限问题。
- 相机、定位、蓝牙、网络轮询、动画和屏幕常亮按作业需要启停；后台不保留无意义的相机流、蓝牙扫描或高频轮询。功耗异常要能定位到具体页面或设备能力。
- 大表格、报表图表、附件缩略图和审批列表采用分页、虚拟化或按需展开；不得用“卡片化”把数百行一次性挂载到手机 DOM。
- 崩溃、白屏、渲染异常、原生桥异常、权限异常和网络错误分类上报版本、设备、WebView、路由和 trace_id；上报数据脱敏且可关联到验收记录。

### 6.8 兼容性、语言和无障碍

- Android 最低支持版本、当前目标版本、主流 WebView 版本及至少两类厂商系统分别验证；权限模型、后台限制、文件选择器、通知权限和蓝牙权限以真实版本为准。
- 字体缩放、系统显示大小、深色模式、动态颜色、中文长文案、英文混排、数字和单位、RTL 不适用性裁定、日期和时区展示都要检查。
- TalkBack 能读出页面标题、字段标签、状态、错误和按钮用途；焦点顺序与视觉顺序一致；弹层打开后焦点不逃逸，关闭后返回触发点。
- 高对比度、色弱、减少动效、触摸目标、键盘导航、系统放大、横屏和低亮度环境都纳入验收。颜色不能是状态唯一信息，图标不能替代文字语义。
- 支持语言的文案、占位符、错误文案、系统分享文件名和权限说明统一核查；不在安卓专项中临时添加裸中文实现，继续遵守前端 i18n 约束。

### 6.9 安装、升级、发布和运维闭环

- 安装来源、签名校验、覆盖安装、降级拒绝、升级后数据保留、卸载重装、清除数据、应用图标、启动页、版本号和隐私说明完整验证。
- debug、release、不同架构、不同 ABI、最小 SDK、目标 SDK 和实际签名产物分别核对；APK 构建成功不等于安装、启动、登录和业务流程成功。
- 发布采用分阶段放量与可回退版本；前端静态资源、服务端 API、数据库迁移和安卓壳版本保持兼容窗口，出现白屏或桥故障时有可执行回退路径。
- 采集安装成功率、启动成功率、登录成功率、白屏率、崩溃率、桥调用失败率、扫码成功率、打印完成率、页面性能和版本分布；指标不采集敏感业务内容。
- 每次发布保留 APK 哈希、签名证书指纹、构建来源、前端资源版本、后端兼容版本、设备矩阵和回滚点；正式发布前必须有 release 包实测证据。

### 6.10 安卓全方面验收分层

安卓验收不是一组“打开几个页面”的冒烟测试，至少分为以下八层，并逐项记录通过、失败、阻塞、未执行和不适用理由：

1. **视觉层**：全路由功能排版、信息层级、字体、间距、颜色、素材、状态和横竖屏。
2. **交互层**：触摸、手势、系统返回、键盘、焦点、滚动、弹层、重复点击和未保存退出。
3. **业务层**：全部业务域的查询、创建、编辑、提交、审批、撤回、删除、导出、打印和结果回读，按权限和状态分面。
4. **设备层**：相机、扫码枪、蓝牙打印、系统打印、文件、分享、通知和外部应用返回。
5. **网络层**：HTTPS、证书、慢网、断网、恢复、超时未知、会话过期、版本更新和服务不可达。
6. **系统层**：安装、升级、权限、后台、锁屏、进程回收、内存、功耗、通知和最近任务快照。
7. **安全层**：可信来源、WebView、令牌、缓存、日志、截屏、外链、导出审批和账号隔离。
8. **发布层**：release APK、签名、ABI、版本兼容、崩溃监控、灰度、回滚与操作手册。

上述八层全部纳入安卓专项的最终放行门；六类代表页只用于先建立版式和组件，不得用代表页通过替代全应用验收。

## 七、弱网、状态恢复与数据安全

部署形态已确认为 HTTPS 公网，弱网方案收敛为同一安全部署基线，不再开发 HTTP 内网兼容分支：

| 环境 | 可实施基础 | 条件能力与禁止项 |
|---|---|---|
| HTTPS 公网 H5 | 网络状态提示、超时分类、保留当前输入、手动恢复；可评估浏览器摄像头与 Service Worker | 有效 HTTPS 满足安全上下文的关键前提，但仍须验证浏览器支持、相机授权、站点策略及 SW 注册作用域 |
| 加载可信 HTTPS 站点的安卓 WebView | 复用 H5 布局和网络恢复；结合现有原生相机授权、蓝牙和系统打印桥 | 摄像头与 SW 的实际可用性按 Android／WebView 版本及宿主配置实测；HTTPS 本身不代表已获原生命令授权 |

Service Worker 作为版本化静态资源缓存和离线提示页的候选实现，不笼统缓存认证 API，不承诺离线业务读写。首次在线加载并成功安装缓存后才能评估离线重开；缓存被清理、更新中断及 WebView 进程重建必须分别测试。HTTPS 不等于自动具备完整 PWA、后台同步或可靠离线冷启动。

第一阶段不自动排队重放出入库、审批、付款等写操作。请求超时可能已经落库，界面显示“结果待确认”，利用现有回读能力与已验证的幂等机制确认后再允许重试；幂等机制必须逐端点核实覆盖，不假定全站具备。

离线阅读只在明确允许的业务数据集上评估；默认不持久缓存客户隐私、成本、权限和认证令牌。若引入持久缓存，至少按部署站点及用户隔离、设置有效期、标明更新时间、退出与切换账号清除、撤权后重新验证。敏感数据不满足撤权与清理条件时不提供离线副本，不能用可被同源脚本访问的密钥制造“已安全加密”假象。

静态资源更新保持版本一致，不能旧 HTML 配新脚本；有未提交表单时不强制刷新。服务器切换时清空站点关联状态，防止跨实例数据串用。

## 八、性能、可访问性与可观测性

性能先测后改，分别定位网络、后端耗时、脚本执行、布局与图片解码。不以一次桌面 Lighthouse 评分代表低端安卓体验。保留按路由加载；图片按需加载；长列表分页或虚拟化，避免卡片化后一次挂载所有历史数据。

建议目标：在约定中档安卓、固定数据与网络基准上，主要页面 p75 LCP 不超过 2.5 秒、INP 不超过 200ms、CLS 不超过 0.1；这些为提议预算，不是当前结果，也不要求断网场景达到同一加载指标。试点测出基线后细分页面预算。

支持 TalkBack、键盘焦点、明确标签及图标按钮名称。长按、滑动、颜色都不能成为唯一操作方式；缩放不被 viewport 禁用。错误提示关联字段，模态层焦点不逃逸，关闭回到触发点。

记录脱敏的页面耗时、扫码启动失败类别、打印阶段与网络错误码，附版本和 trace_id；不记录完整条码内容、客户信息或认证数据。业务审计仍由既有后端链路负责，不以客户端日志替代。

## 九、页面盘点和迁移治理

“全方位”意味着所有可达页面都有结论，而不是一次性修改全部 Vue 文件。实施第一步建立页面矩阵，每项至少含：真实路由、页面类型、业务域、允许角色、主任务、使用频率、风险、现有适配、关联组件、手机／平板／桌面布局、测试证据、负责人、验收状态。

分母从路由、导航和遍历清单互核，去除重定向重复项；页内 Tab、弹窗和重要状态另列子项，不用 377 个文件冒充 377 个页面。功能未获权限时使用独立授权测试账号，不以管理员一测代替全角色。

适配进度只认“已执行且通过的页面×状态×设备项／本波计划项”。静态存在、未执行、阻塞、失败和跳过分开列出；全部上线前每个在册页面必须验收或获得明确范围裁定，不能以试点通过宣布全站完成。

## 十、优先级与分阶段实施建议

P0 为交付前必须关闭的安全／数据正确性风险，不意味着本报告已复现漏洞；P1 为核心业务与移动可用性；P2 为全域一致性和低频场景。

| 波次 | 内容与明确交付物 | 进入与退出条件 | 粗估人日 |
|---|---|---|---:|
| W0 安卓全量基线与设计 | 全部路由／功能矩阵；6 类代表页只是样板；安装启动、账号、生命周期、设备、权限、网络、性能、安全、发布基线；安卓手机信息架构与触摸规范 | 用户确认全量范围；收齐设备与环境基线；不改业务规则 | 8 至 14 |
| W1 安卓壳与通用布局 | 启动／登录／导航／列表／详情／表单／弹层模板；键盘安全区；系统返回；可信来源与最小原生信任收敛 | 代表样板和壳层跑通，窄屏、横屏、桌面回归齐全；安全疑点有结论 | 14 至 22 |
| W2 高频业务与设备作业 | 全部核心业务的手机功能排版；仓库/PDA、审批、销售采购；扫码、蓝牙和系统打印链；防重回读 | 核心链按角色和状态真实验证，硬件路径有实机证据 | 18 至 30 |
| W3 数据、媒体与恢复 | 图片/附件、单据、下载分享、通知深链、弱网、会话恢复、缓存、性能和无障碍 | 数据隔离、超时未知态、版本更新、外部返回和异常恢复均通过 | 14 至 24 |
| W4 全域迁移 | 生产质量、财务报表、物流、人事、合规、资产、系统管理及剩余页面逐域迁移；低频域不得默认豁免 | 全部页面和八层安卓验收矩阵闭环，无以文件数替代完成率 | 按矩阵重估 |
| W5 发布与交付验收 | 跨设备回归、可访问性、性能、发布 APK、签名、安装升级、监控、灰度回滚及操作说明 | release 包与全量证据齐备，无未关闭阻断项 | 10 至 18 |

W0、W1、W2、W3、W5 合计约 64 至 108 人日，为覆盖安卓全量范围、设计、开发、测试、复审、设备联调与发布验证的初步投入估算，不是完成全站的承诺工期。W4 尚无有效页面分母，不能诚实给出固定总价或总工期；全量安卓范围扩大后，原先 43 至 70 人日估算已失效。试点后以简单布局页约 0.25 至 0.5 人日、中型交互页约 0.75 至 1.5 人日、复杂编辑／硬件流程约 2 至 4 人日、原生桥或发布安全专项约 3 至 8 人日作重新估算起点，按独立页面模板和实际复用校准，避免重复计算 W2/W3 已完成页面。

共享模板、主题、主壳由单一负责人收敛；业务域前端与安卓桥可在互不重叠文件上并行，测试负责人独立验收。W0 先于 W1，W1 模板稳定后才扩 W2/W4；W3 的硬件和网络评估可提前开展，但集成依赖 W1。四人并行不意味着总人日直接除四。

## 十一、验收矩阵与放行规则

### 11.1 设备与环境

- 手机宽度：320、360、393、412 CSS px；断点边界：768/769、991/992；桌面回归：1280、1440。
- 横屏必须真实切换状态，不以 820 宽竖屏截图冒充旋转测试；窄平板补主从布局检查。
- H5 Chrome 与 Android WebView 分开验；安卓最低支持版本、权限变化关键版本及当前目标版本分别核定，至少两类厂商手机和实际 PDA。
- 实际安卓版本、WebView、扫码枪、打印机型号在 W0 固定；纸宽、协议和连接方式记录在测试报告中。
- HTTPS 公网正常链路、HTTP 降级拒绝、不受信任来源、混合内容、慢网、断网、证书错误、登录失效和账号切换各自设用例；H5 与 Android WebView 分别验证摄像头及 SW 能力，不以其中一端通过替代另一端。

### 11.2 建议硬门槛

| 验收面 | 判据 |
|---|---|
| 布局 | 文档级横向溢出不超过 2px；关键内容不被裁切；表格内部横滚可接受但须有识别列与提示 |
| 输入 | 键盘弹出后焦点与保存入口可达；旋转和切后台不误提交；200% 字体下仍可完成主流程 |
| 操作 | 常用触摸目标达到设计尺寸；无手势也可操作；确认与取消路径均覆盖 |
| 业务正确 | 连点、超时、重复扫码不会产生非预期重复写；提交成功必须由真实数据回读确认 |
| 权限 | 入口、操作、数据及原生桥来源四层分别验证；无权限不泄露敏感摘要或缓存 |
| 扫码 | 约定光照与标签集下测试100次，建议正确识别至少99次；错误码不能被当成正确单据受理 |
| 打印 | 连接、权限、断连和取消有明确结果；指定样张中文及条码可读；桥调用成功与出纸分开记录 |
| 异常恢复 | 模拟结果未知时先回读，不盲目重放写操作；换账号、换服务器不显示上一身份数据 |
| 视觉与无障碍 | 字体、间距、颜色、素材、文案、焦点和状态逐项对照批准设计；人工与自动报告互补 |
| 回归 | 计划内核心链100%通过，P0/P1阻断为0；桌面和发布APK均有对应提交证据 |

目前既有移动断言继续保留并扩展，不因重排布局而放松“可操作、无溢出、真实写回”的判据。涉及有意设计变化时更新语义定位和批准截图，而不是扩大容差消红。原生桥桩只证明前端调用契约，真实相机、蓝牙和系统打印必须用模拟器或硬件另证。

本报告不调整 CI。后续若新增工作流或 job，先明确授权与配置范围，并核对收尾聚合门；不能把主 CI 中 run_e2e=false 的 APK 构建当成移动业务全绿。按项目验证边界安排 CI 与授权设备环境，未执行项必须保留“未验证”。

## 十二、风险与回退

- 全局 CSS 覆盖面大：先按页面类型隔离改动，避免所有表单一次套新模板；已有全局规则待逐页证明可替代后再退役。
- 双布局分叉：数据与业务动作共享，只拆表现层；防双挂载重复请求和隐藏 DOM 泄露数据。
- 底部导航遮挡：与软键盘、业务操作栏、安全区统一协调，不多层固定定位叠加。
- 全面卡片化影响比较效率：财务与密集明细保留局部滚动表格，不强推统一样式。
- 缓存泄露和离线错单：首阶段不做自动离线写；敏感数据不满足失效机制即不缓存。
- 硬件差异：以实机协议为准，未支持设备明确说明，不增加“尝试成功”式提示。
- 分波回退：UI布局改动与业务语义分离，每波有独立可回退提交；回退不能移除已建立的安全约束。不新造长期双轨功能开关。

## 十三、下一步与未决项

推荐先批准 W0 的安卓全量盘点与代表页设计，再审定导航、页面模板、系统生命周期、设备能力及发布验收基准后实施 W1。代表页至少覆盖工作台、销售列表、采购编辑、扫码作业、审批待办、对账报表六类，并附加载、空、错误、无权限、离线、后台恢复、权限拒绝和版本更新状态。六类代表页仅是版式样板；全量路由、功能、角色、设备能力和发布链路必须按 6.10 八层矩阵逐项收口。

部署前提已明确为 HTTPS 公网，不再列作待决项，也不保留 HTTP 内网支持分支。进入硬件实施前再核实实际 PDA／打印机型号、Android 与 WebView 版本、最低支持范围；进入持久缓存前再确认允许离线的数据范围。这些是有期限的实施前置，不是将整体优化搁置的理由。

本次交付仅为全方位评估建议：不修改业务源码、权限配置或 CI，不创建分支、提交、PR，不推送，不把小程序缺口混入本方案。
